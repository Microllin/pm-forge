# @pmforge/chat

独立对话服务：pi 集成 + pi 版本升级 + web 对话。

```bash
pnpm dev              # 仓库根执行：服务 http://127.0.0.1:4400 + 前端 http://127.0.0.1:3200
```

首次使用：打开前端 → 设置 → 模型接入，添加自定义中转（用 key 拉取 /v1/models 后勾选模型）或 pi 内置 provider → 新对话。

对话中切换模型（照 pi CLI）：点输入框左下角的模型名、输入 `/model [搜索词]` 回车，或按 Shift+Tab 切思考强度。切换写进会话 transcript，重开会话时按它恢复；每条回答标注实际作答的模型。

对话里手动点名技能：输入 `/skill` 回车弹选择器（可搜索，隐藏的技能也列出来），选中后把 `/skill:名字 ` 填回输入框再补一句要做什么；也可直接打 `/skill:名字 参数`。服务端会把该技能的 SKILL.md 正文真正注入这一轮（不靠模型自己决定调工具），历史里仍只显示你打的那行命令。

技能（skill）：左侧「技能」页是「左列表 + 右展览」——列表可搜索（名称与描述），详情默认看**渲染后的** SKILL.md、可点开附属文件、可在此分发；要改再点「编辑」切源码。新增技能有三条路：新建（预填骨架）、导入 `.md` / `.zip`、**导入文件夹**（选技能自己的目录就导一个；选装着若干技能目录的那一层就批量导，逐个报成败），也可软链分发到 `~/.claude/skills` 与 `~/.agents/skills` 给命令行用。技能存在 `{数据目录}/skills/<名字>/SKILL.md`，**每轮对话现场重扫**，所以改完下一轮即生效，不必重开会话。模型看到的只有名字与描述，任务对得上时它用 `skill` 工具加载正文——该工具只能读技能目录内的文件，服务不开 read / bash / edit / write。

执行体（agent）：左侧「执行体」页与技能页同构（左列表 + 右展览）。**技能是操作手册，执行体是照手册干活、且配好工具权限的人**——两者是组合关系不是升级关系，所以并列成两个一级菜单。一个执行体 = 一份 `<名字>.md`（不是目录），存在 `{数据目录}/agents/`，可新建（预填带 tools 与纪律的骨架）、导入 `.md`、就地改、软链分发到 `~/.claude/agents`。列表行与详情都把 **tools / model / skills** 直接摆出来：它们决定「派它出去会发生什么」。两个硬提示——没写 `tools` 等于**继承全部工具**（含写与 Bash），会标「可写」；`skills:` 点名了技能库里没有的名字会标出来，因为那会让它照样启动、手册却悄悄没了。

**现在它只管定义与分发，PMForge 的对话还派不出去**：pi 1.2.0 没有子 agent 能力。真做派发（起一条受控 pi 会话跑任务、回传运行记录）是下一步的独立工作，届时按名字从同一个库取定义，不会出现第二份真相源。模块规则与接口见 `server/agents.ts`。

上游失败时 pi 会自动重试，界面会显示一行「上游失败，正在自动重试（第 N / M 次）」并在恢复后改成「已恢复」——否则你只会看到一段更长的空白，分不清它是在想还是卡了。该提示是过程信息，不进会话历史（pi 的 transcript 里也不留失败那次）。

思考过程（reasoning）一直是 SSE 实时下发的（`reasoning-start/delta/end`）。界面怎么显示在「设置 → 界面 → 思考过程」里选：折叠（默认）/ 边想边看（思考时自动展开、答完自动收起）/ 始终展开；偏好存本机浏览器。注意有些模型是自适应思考（如 Claude Opus 5.5），简单问题它根本不思考，这时哪档都不会有思考过程。

| 环境变量                                      | 默认              | 说明                                                                                          |
| --------------------------------------------- | ----------------- | --------------------------------------------------------------------------------------------- |
| `PMFORGE_CHAT_DATA_DIR`                       | `~/.pmforge-chat` | 数据库、key 文件、pi 配置目录                                                                 |
| `PMFORGE_CHAT_KEY_<PROVIDER>`                 | —                 | 某个 provider 的 key（大写、`-` 换 `_`，如 `PMFORGE_CHAT_KEY_RELAY`），优先于已保存的，不落盘 |
| `PMFORGE_CHAT_PORT` / `PMFORGE_CHAT_WEB_PORT` | 4400 / 3200       | 端口                                                                                          |
| `PMFORGE_CHAT_ALLOWED_ORIGINS`                | —                 | 额外放行的 Origin（逗号分隔）                                                                 |
| `PMFORGE_CHAT_FILE_LIMIT_MB`                  | 2048              | 文件模块单个文件的上传上限（MB）；上传边收边写盘，不占内存                                    |

服务只监听 127.0.0.1，没有登录；Host / Origin 校验挡 DNS rebinding 与跨站请求。
服务由 `server/supervisor.ts` 看护：pi 升级成功后以退出码 75 请求重启。

## 一级菜单

左侧品牌导航按三组排：**工作台**（对话 / 产品）、**资料**（文件 / 技能 / 执行体）、**系统**（设置）。
当前位置记在 URL hash：一级是 `#chat` / `#products` / `#files` / `#skills` / `#agents` / `#settings`，
带二级标签的形如 `#products/lifecycle`。

- **事实底座**：两个二级入口，**同一个文件库的两个视角**。
  - **文件**（`#files`）：文档资料，从 `/` 起。
  - **代码**（`#files/code`）：代码库，从 `/代码库` 起。面包屑与搜索都裁到这个根，
    不会漏出另一个入口的内容。
    能力两边一致：文件夹与文件的增删改查、复制、多选批量（移动 / 复制 / 打包下载 / 删除）、
    上传文件或整个文件夹、按名称与内容搜索、在线预览（Markdown / 文本 / HTML / 图片 / PDF）与代码高亮编辑。
    东西放在 `{数据目录}/files`（Finder 里可直接看到），`files.db` 只是索引。
- **产品**：两个二级标签。
  - **产品**（`#products`）：产品线与产品的增删改查，并给每个产品绑一份生命周期规范与一个文档目录。
    接口 `/api/product-lines`、`/api/products`。
  - **图谱**（`#products/graph`）：三张图 + 产品 wiki。
    - **产品全景**：泳道=产品线、卡片=产品、按产出物齐备度着色。双击钻进去。
    - **生命线**：阶段 L0.1→L5.2 横向排开，产出物挂在阶段下。
    - **功能架构**：AI 读代码分析出的一级/二级/三级…功能树，每个节点都能再「向下拆一层」
      或「重新分析这一支」。 接口 `/api/analysis/architecture`、`/api/products/:id/features`、`/api/feature-nodes/:id`。
      点任一节点开详情抽屉（职责、代码证据、判定要点全文、漏了哪几条）。
      React Flow 单独分块，点进来才下载。
  - **生命周期规范**（`#products/lifecycle`）：模板库——一套模板就是「这类产品从 0 到 1 该走哪些阶段、
    每个阶段该交什么」。接口
    接口 `/api/lifecycle-templates`、`/api/lifecycle-stages`、`/api/lifecycle-artifacts`。

三块数据都在同一个 `chat.db`，走同一个服务的安全闸与错误处理。

## AI 分析

两个入口，**都跑在真对话里**（看得见过程、能追问、能停、刷新续流）：

- **AI 识别产线与产品**（产品页）：选一个目录（如传进「文件」里的 product-docs），
  读它的目录结构与 README / `*.yaml` 判断里面有哪些产线与产品。**结果先过确认表再落库。**
- **AI 比对产出物**（产品行）：对照该产品绑的规范模板，逐件核对在不在、答没答全，
  结论分 齐 / 不全 / 缺 三档；存最近一次，产品行上显「上次比对 3/13 齐」。

接口 `/api/analysis/*`、`/api/product-checks`。目录事实由**服务端采集**后喂进提示词——
对话会话没有文件工具（`noTools: "all"`），给 agent 开 read/bash 等于绕开 `files/paths.ts` 的越界闸。
