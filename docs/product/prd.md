# PMForge MVP 产品需求文档

> 版本：v0.1 | 状态：需求设计中 | 当前步骤：Step 0 上下文确认

## 1. 产品定义

PMForge 是一个以自然语言对话为核心交互、以高质量 PRD 为核心专业产物，并逐步连接软件全生命周期工作的 AI 产品经理工作空间。

核心转换：

```text
自由对话：探索、发散与临时工作
        ↓ 用户选择绑定
Work Item：可持续推进、可追溯、可执行的软件工作
```

## 2. 已确认的产品原则

1. 自然语言对话是核心工作入口，不是附属聊天功能。
2. 对话不强制绑定 Work Item。
3. 一旦绑定 Work Item，后续正式工作必须归属于该 Work Item。
4. 高质量 PRD 生成是 MVP 的核心专业能力，包含需求提炼、产品判断和产品设计，不只是扩写文本。
5. 软件全生命周期是覆盖范围，但 MVP 不预先实现所有环节。
6. 生命周期外围能力按照真实需求逐步增加，不固定完整模块和流程。
7. 不强制固定 SDLC、阶段、质量门或 Next Action。
8. 第一期映射用户已有本地目录，以真实文件为事实来源。
9. 支持多个可命名根目录；文件树结构由用户自行组织。
10. 通过类似 `PMFORGE.md` 的目录说明文件补充目录语义和操作边界。
11. AI 能力按观察、协调、执行逐级授权；执行权限绑定具体动作。

## 3. 目标用户

待确认。

当前候选：

- 日常需要完成需求分析、产品设计和 PRD 的 AI 产品经理；
- 能接受本地目录和自然语言 Agent 工作方式的个人产品经理或小团队；
- 需要把产品需求继续推进到研发、测试和交付的产品负责人。

## 4. 产品形态

待确认。

当前候选：桌面优先的本地工作空间，或本机运行的 Web 工作台。

## 5. MVP 核心问题

待确认。

当前假设：产品经理已经在本地工作目录中持续产生文档、修改和工作痕迹，但通用 AI 不理解这些材料代表的工作流程，用户不得不重新描述背景和手动创建任务。PMForge 应先理解现有目录，识别正在发生的产品工作，再由用户确认创建一个可以持续承载目标、上下文、产物、动作和结果的 Work Item。

## 6. MVP 核心闭环

待后续步骤确认。

初步骨架：

```text
选择现有产品工作目录
→ PMForge 读取目录说明、结构和授权范围内的工作痕迹
→ 理解该目录中的产品经理工作方式
→ 给出带依据的候选 Work Item
→ 用户确认、修改、合并或忽略
→ 创建 Work Item 并自动关联初始上下文
→ 进入自然语言工作空间继续澄清和推进
→ 形成或修改 PRD
→ 审查差异并写回原文件
→ 保存 Work Item 上下文、产物和操作结果
```

手动自由对话和手动创建 Work Item 仍作为入口保留，但不再是唯一的 MVP 起点。

## 7. MVP 范围

MVP 必须包含五个一级区域：

| 区域           | MVP 职责                                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------- |
| 主工作区       | 固定主对话承载自由探索或绑定 Work Item 的正式工作；文件、PRD、Diff和执行结果按需打开为工作标签页  |
| 任务区（导入） | 浏览、搜索和导入外部任务；由用户选择创建新 Work Item、绑定已有 Work Item或只发送到自由对话        |
| 文件区         | 映射多个真实本地目录；文件或目录路径可拖入主工作区成为事实底座，不预先区分代码、PRD或其他文本材料 |
| Skill 区       | 浏览本地已安装 Skill；支持手动选择以及 AI 推荐/自动路由，用户可查看、移除和替换                   |
| Work Item 区   | 创建、浏览和恢复正式工作；承载最小状态、父子关系、目标、对话、事实底座、Skills、产物和操作记录    |

关系原则：主工作区是核心；任务、文件和 Skill 为其提供输入、上下文与能力；Work Item 为正式工作提供持续归属。

### Work Item 最小模型

```text
Work Item
├── 标题
├── 目标
├── 状态：Active / Paused / Done
├── 父 Work Item（可选）
├── 子 Work Items
├── 外部来源任务（可选，可多个）
├── 事实底座（文件或目录）
├── 对话
├── 实际使用的 Skills
├── 产物
└── 操作记录
```

约束：

- 一个 Work Item 最多有一个直接父项，可以有多个子项；
- 父子项分别维护目标、状态、对话和操作记录；
- 父项状态不因子项状态自动流转；
- MVP 不提供依赖图、关键路径、自动排期和复杂任务编排；
- 状态不映射为固定 SDLC 阶段。

## 11. 信息架构与用户流程

一级信息架构：

```text
PMForge
├── 主工作区 Workspace
├── 任务区 Tasks（导入）
├── 文件区 Files
├── Skill 区 Skills
└── Work Item 区
```

五个区域的具体页面层级、侧栏结构和可组合方式待下一步设计，不在当前阶段直接固定为某种三栏布局。

### 主工作区结构

```text
Workspace
├── 固定主对话
│   ├── 对话流
│   ├── 自然语言输入
│   ├── 当前 Work Item 绑定状态
│   └── 当前事实与 Skill 提示
└── 按需工作标签页
    ├── 文件
    ├── PRD / Markdown
    ├── Diff
    └── 执行结果
```

规则：

- 主对话是连续的工作主线，不被文件全文和大型结果淹没；
- 标签页与主对话共享当前上下文；
- 用户可以从对话打开产物，也可以从文件区拖入路径打开标签页；
- 关闭标签页只关闭视图，不删除底层文件、产物或 Work Item 关联；
- 是否支持并排拆分布局不属于当前已确认范围。

### 文件事实导入流程

```text
从文件树拖入本地文件或目录路径
→ PMForge 在授权边界内登记事实来源
→ 单文件直接读取；目录建立可检索范围
→ 将路径加入当前对话或当前 Work Item 的事实底座
→ 后续根据问题按需搜索和读取相关文件
→ 回答和产物可引用具体事实
```

约束：

- 第一期使用统一文件事实机制，不预设代码、PRD、研究材料等业务分类；
- 支持拖入单个文件和整个目录；
- 目录按需搜索和读取，不一次性将全部正文装入模型上下文；
- 自由对话中的文件归属于当前对话；Work Item 模式中的文件持续关联当前 Work Item；
- 正式文件仍以原本地路径为事实来源，不复制影子正文；
- PMForge 保存路径、内容指纹、关联和必要索引；
- 修改文件时必须展示 Diff，并由用户确认写回；
- 不允许访问用户未授权目录边界外的路径。

### Skill 使用流程

```text
用户提出自然语言意图
→ PMForge 匹配本地已安装 Skill
→ 展示或标记推荐/已路由 Skill 及原因
→ 用户可保留、移除、替换或手动拖入其他 Skill
→ Skill 参与当前对话或 Work Item 工作
→ Work Item 记录实际使用过的 Skill
```

MVP 范围：

- 浏览、搜索本地已安装 Skill；
- 查看用途、触发条件和说明；
- 手动选择或拖入主工作区；
- AI 推荐或自动路由；
- 用户查看、移除和替换；
- Work Item 记录实际使用的 Skill。

MVP 不包含：

- Skill 市场；
- 在线安装和升级；
- 可视化 Skill 编排；
- 自动生成 Skill；
- 复杂 Skill 权限管理。

### 外部任务导入流程

```text
选择外部任务
→ 查看任务详情与来源
→ 选择进入方式
   ├── 创建新 Work Item
   ├── 绑定已有 Work Item
   └── 只发送到自由对话
→ 进入主工作区
```

约束：

- 不因浏览、点击或导入任务而静默创建 Work Item；
- 外部任务和 Work Item 保持独立身份；
- 同一外部任务重复导入时，应识别已有绑定并避免重复创建；
- 任务来源的远程写操作不在导入动作中隐式发生。
